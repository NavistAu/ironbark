# ironbark M1 Broker Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the M1 broker exactly as specified in [`docs/SPEC.md`](../SPEC.md) (ACCEPTED 2026-07-11): a Go binary implementing Woodpecker's secret extension against Vault/OpenBao.

**Architecture:** Stateless HTTP service: verify RFC-9421 signature → parse identity → derive conventional policies → mint an orphan non-renewable service token (canary-gated) → sweep the conventional KV subtree with that token → return masked secrets + the token. Packages per SPEC §10; every behavior in this plan cites its normative SPEC section — **SPEC.md is the source of truth; this plan sequences it**.

**Tech Stack:** Go ≥1.24 (mise-managed), stdlib `net/http` + `log/slog`, `github.com/yaronf/httpsign`, `github.com/hashicorp/vault/api`, `github.com/prometheus/client_golang`. Tests: stdlib `testing` (+ fuzz), `httptest` fakes for unit, docker-compose Vault **and** OpenBao for integration.

**Plan style note:** Per the repo owner's standing rules this plan is a spec, not a diff — steps give signatures, exact behaviors, test enumerations with expected values, and commands; the implementer writes the code. "Write the failing test" steps enumerate the exact cases and assertions; they do not paste test bodies.

**Conventions for every task:**
- TDD: failing test → confirm fail → implement → confirm pass → commit.
- Run unit tests with `go test ./internal/... -run <Name> -v`; full sweep `go test ./...`.
- Commit after every green step, message prefix `feat:`/`test:`/`chore:`.
- Typed errors over sentinel strings; no panics on request paths.

### Task 5: `wpsign.Verify` + signature matrix

**Files:** Create `internal/wpsign/wpsign.go`, `internal/wpsign/wpsign_test.go`.

Signature and taxonomy (SPEC §5):
```go
type Reason string
const (ReasonMissingSignature, ReasonUnparseable, ReasonWrongKey, ReasonDigestMismatch,
       ReasonUncoveredComponent, ReasonMissingCreated, ReasonStaleCreated Reason = …)
type VerifyError struct{ Reason Reason; Err error }   // implements error
func Verify(r *http.Request, body []byte, pub ed25519.PublicKey, window time.Duration, now func() time.Time) error
```
Normative behavior: signature must verify with the configured key; covered components MUST include `@request-target` and `content-digest`; the `Content-Digest` header MUST match the actual body (compute RFC-9530 `sha-256=:…:` and compare if the library does not already — the tampered-body test decides); `created` REQUIRED; reject when `|now − created| > window`. No payload data used or logged.

- [ ] **Step 1: Failing matrix test** `TestVerifyMatrix` — build requests with `wpsigntest`, one subtest per SPEC §9.1 row, asserting the exact `Reason`:
  | case | expect |
  |---|---|
  | valid, fresh | nil error |
  | no Signature/Signature-Input headers | ReasonMissingSignature |
  | signed with different key | ReasonWrongKey |
  | body swapped after signing | ReasonDigestMismatch |
  | Content-Digest header stripped after signing | ReasonDigestMismatch (or MissingSignature-class — pin whichever the implementation yields, but it MUST reject) |
  | components = only `@request-target` | ReasonUncoveredComponent |
  | OmitCreated | ReasonMissingCreated |
  | created = now−11s (window 10s) | ReasonStaleCreated |
  | created = now+11s | ReasonStaleCreated |
  | byte-identical replay within window | nil error (accepted — documented) |
- [ ] **Steps 2–4:** FAIL → implement over `yaronf/httpsign` verifier APIs → PASS. Implementation note: consult the httpsign v0.5.x `Verifier`/`VerifyConfig` for created-window knobs (`SetNotNewerThan`/`SetNotOlderThan`); where library defaults differ from the SPEC window, configure explicitly from the `window` argument. Do not trust the library to check body-vs-digest — prove it with the matrix; add an explicit check if the tamper case passes.

### Task 9: `vaultx` sweep, deref, directives

**Files:** Create `internal/vaultx/sweep.go`, `internal/vaultx/sweep_test.go`.

```go
type SweptSecret struct{ Name, Value string; Images, Events []string }   // Events empty = default pin applied later
type SweepResult struct{ Secrets []SweptSecret; LeasesCreated bool }
func (c *Client) Sweep(ctx, token string, id identity.Identity, branchful bool) (SweepResult, error)
func (c *Client) ReadIdentity(ctx, token, base string) (forgeID *string, err error)   // ErrMalformedDirective typed
func (c *Client) ReadConfig(ctx, token, base string) (map[string]string, error)       // ErrMalformedDirective typed
```
Normative (SPEC §4.1–§4.3, §4.6): three independent LISTs most-specific-first (branch level only when branchful ∧ branch≠""); within a level lexicographic; plain keys only, never descend; skip ANY dot-prefixed key at every level; 403/404 → skip level/entry; any other status → typed error (bubbles to 502). Entry forms: `{"$ref": path}` exact → one-level deref with the SAME token (`lease_id` non-empty ⇒ LeasesCreated); `{"value": v}` exact → secret `E`; else `E_f` per field. String-only values (skip+warn). Name mapping: lowercase, `-`→`_`, validate `[a-z0-9_]+` else skip+warn. Collisions: first-writer-wins (⇒ most-specific wins). Pins from data-GET `custom_metadata` keys `ironbark_images` / `ironbark_events` (comma-split, trimmed); NO metadata-GET fallback.

- [ ] **Step 1: Failing tests** (httptest fake KV v2 — fake serves `?list=true` on `/v1/kv/metadata/...` and data on `/v1/kv/data/...`):
  - Tier independence: base LIST 403, event LIST 404, branch LIST OK → branch secrets returned, no error.
  - Precedence: `token` defined at base and at branch with different values → branch value wins.
  - Dot-skip: `.identity`, `.config`, `.weird` listed → never in Secrets.
  - Forms: shorthand → name `E`; general `{user, pass}` → `e_user`, `e_pass`; `-`→`_`; invalid name `münz` field → skipped, sibling survives; non-string `{count: 3}` → skipped with sibling surviving.
  - Deref: `$ref` → fields flattened `E_f`; fake returns `lease_id` → LeasesCreated true; deref 403 → entry skipped; deref 500 → typed error.
  - No-chain rule (SPEC §4.3): a deref whose response data is exactly `{"$ref": "other"}` is NOT followed again — assert the fake receives no second deref request; the `$ref` field name fails `[a-z0-9_]+` validation and is skipped with a warning, so the entry yields no secrets.
  - Lexicographic determinism: same-tier keys `a-b` and `a_b` (fake LIST returns them unsorted, values differ) both normalize to `a_b`; implementation must sort keys before reading; `a-b` < `a_b` lexicographically, so the secret `a_b` carries `a-b`'s value and the collision is logged.
  - Pins: custom_metadata `ironbark_images: "img1, img2"` → Images `[img1 img2]`; `ironbark_events: "push,cron"` → Events.
  - Directives: `.identity` valid → forgeID; `{"forge_remote_id": 7}` (number) → ErrMalformedDirective; absent → (nil, nil); `.config` non-flat-string-map → ErrMalformedDirective.
  - Any LIST 500 → typed error.

### Task 10: `broker` orchestration

**Files:** Create `internal/broker/broker.go`, `internal/broker/broker_test.go`.

```go
type Vault interface {           // implemented by *vaultx.Client; mocked in tests
    CanaryOK() bool
    MintToken(...) (vaultx.Mint, error)
    RevokeSelf(ctx, token string) error
    ReadIdentity(...) (*string, error)
    ReadConfig(...) (map[string]string, error)
    Sweep(...) (vaultx.SweepResult, error)
}
type Secret struct{ Name, Value string; Events, Images []string }
type Outcome string  // ok | unonboarded | identity_mismatch | error
type Result struct{ Status int; Secrets []Secret; Outcome Outcome; Audit AuditFields }
type AuditFields struct{ PoliciesRequested, PolicyWarnings, SecretNames []string; TokenAccessor string; TokenTTL time.Duration }
func (b *Broker) Handle(ctx, id identity.Identity) Result
```
Normative sequence = SPEC §1.2 steps 5–10 exactly. The broker computes
`branchful := policy.Branchful(id.Event)` and passes it to `Sweep`
(GP2-2 — the branch tier is swept only for branchful events with
non-empty branch, mirroring P2 derivation). Including: canary gate (fail/unknown → 502, NO mint); mint; token_type assertion (≠service → revoke best-effort, 502); all-policies-warned → revoke, 204 unonboarded (warning match: a warning naming each requested policy — parse `Policy "<name>" does not exist`); identity mismatch/malformed → revoke, 204; `.config` malformed/5xx → revoke, 502; sweep/deref typed errors → revoke, 502; response build: default event pin = `[id.Event]` when SweptSecret.Events empty; `vault_token` unless `.config["vault_token"] == "false"`; `vault_addr` when configured, never counted for emptiness; empty+suppressed → revoke, 204; revocation-by-outcome invariant: **every non-200 revokes; 200 never revokes**.

  canary-failed→502/no-mint/no-revoke-call; happy→200 secrets+vault_token+pins, no revoke; unonboarded→204+revoke; identity mismatch→204+revoke; identity malformed→204+revoke; identity 5xx→502+revoke; config malformed→502+revoke; sweep 5xx→502+revoke; deref lease then sweep failure→502+revoke (leases cascade note); type=batch→502+revoke-attempt; suppressed+empty→204+revoke; suppressed+empty+advertise-addr→still 204 (C7); vault_addr present when configured on 200.
